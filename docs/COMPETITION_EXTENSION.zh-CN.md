# 聚场：通用活动与赛事模块扩展研究

2026-10-22。本文区分现有能力与后续设计，不表示其他运动的赛事规则已经可用。

## 当前边界

聚场的核心是场地时段管理、活动报名和群机器人交互。会员、审核、正式/替补名额、同行代报、场地占用、历史记录和通知无需绑定某项运动。球馆、活动教室、工作坊和其他社群空间可使用这些模块组织活动。

现有赛事引擎仍以羽毛球为对象：单打/双打、男双/女双/混双、等级分配、羽毛球记分和五人轮转等规则有明确的项目含义。当前不能用羽毛球比分校验去处理篮球、桌游或其他比赛，也不把等级 1–9 自动解释为这些项目的等级。

## 建议拆分

| 层次 | 管理内容 | 当前可复用部分 | 后续需要补充 |
| --- | --- | --- | --- |
| 活动与报名 | 场地、时段、容量、报名名单、参与资格 | `service.py`、场地占用及会员模块 | 活动模板与可选的项目标签 |
| 队伍生成 | 每队人数、固定队/临时队、分配策略 | `formats/common.py` 的随机种子和分配思想 | 独立的队伍模型、人数约束、项目内能力标签 |
| 对战结构 | 单/双败、循环、小组晋级、轮次 | `formats/` 的独立 Python 规划器 | 与项目无关的参赛实体及晋级接口；瑞士制等新规则 |
| 项目规则 | 记分单位、局制、胜负、平局、弃权 | 当前羽毛球校验与赛事结果记录 | 每项目的独立规则适配器 |
| 排程与执行 | 场地占用、并行场数、休息、裁判 | 当前赛事协调和临时职务 | 可配置的对局时长、最短休息、冲突检查 |
| 交互与通知 | 群内操作、权限、机器人范围、历史 | 现有机器人、通知和权限模块 | 按活动模板提供字段与帮助，禁止越权调用 |

对战结构和每场比赛的计分规则应分别配置。Toornament 将单场、主客场、若干局决胜等比赛形式与赛事的阶段结构分开，并允许下层覆盖上层设置。这支持上述拆分思路；不是直接照搬其数据模型。[官方比赛形式说明](https://help.toornament.com/match/define-your-match-format)

Challonge 分别提供单败、双败、循环、瑞士制等结构，并支持小组阶段连接决赛阶段。通用化应先覆盖已有结构的复用，再逐个引入新结构及相应的晋级与排名测试。[官方赛制说明](https://kb.challonge.com/en/article/learn-about-challonge-competition-formats-1f8j1cf/)

## 目标流程

创建活动 → 配置报名 → 确认参赛名单 → 选择组队策略 → 预览对战表 → 确认排程 → 记录比赛 → 发布结果与归档。

不需要比赛的活动，在报名和活动记录阶段即可完成。需要组队但不计胜负的活动，可在分组后结束；不用强制生成对战表。

每个比赛实例应冻结 `sport_profile`、`team_policy`、`draw_format`、`scoring_rules`、规则版本、随机种子和参赛名单快照。管理员修改模板只影响后续创建的赛事。重排赛程或修正比分应保留版本与操作记录；恢复比赛读取已保存状态，不根据新报名名单静默重新抽签。

## 分步落地

1. **先分离现有羽毛球适配器。** 保持旧指令、历史赛事和结果兼容，将双打性别约束、1–9 级标签解释、局分校验放进项目规则模块。对相同名单、参数和随机种子核对改造前后的排赛结果。
2. **再加入通用报名与组队模板。** 先支持无计分活动、固定队伍、随机分组。名单确认、组队预览和确认发布分开；活动负责人和机器人范围仍由现有权限层校验。
3. **逐项增加对战规则。** 优先复用循环、小组晋级与淘汰结构，再实现项目计分适配器。瑞士制、计时排名、积分排行榜等单独验收，不能仅改页面名称就宣布支持。

验收必须包含：奇数人数及轮空、重复/缺失参赛者、同人同时参赛冲突、重名和代报名身份、多人改分冲突、跨日恢复、已结束比赛不可重抽、机器人功能范围、负责人权限，以及每个项目的比分边界。

## 这次已交付

- 产品更名为聚场 GatherSpace，主页和说明采用通用场地、活动与群机器人定位。
- 定时播报归入“机器人与群”，机器人设置提供入口，可筛选查看对应规则。
- 保留现有播报规则的数据和调度行为；赛事页面和说明明确目前支持羽毛球。
- 通用赛事规则拆分仅形成此研究与实施边界，尚未开放其他项目的计分或对战规则。
