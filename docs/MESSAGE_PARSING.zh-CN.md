# 统一消息解析

[English](MESSAGE_PARSING.md) · [对接说明](INTEGRATION.zh-CN.md)

## 处理流程

```text
回调认证 / 后台演练认证
  → MessageInput（原文、格式、可选提及范围）
  → normalize_message（验证原文提及位置、清洗样式、移除开头机器人提及）
  → CommandText（业务正文，不携带身份或权限）
  → parse_selection（场地、日期、场次）
  → Commands（固定业务 / AI 流程）
  → 原有业务开关、范围、会员资格及操作权限校验
```

`app/message_parser.py` 负责提及边界和输入校验，`app/message_styles.py` 负责排版清洗，`app/input_formats.py` 负责数字与明确日期；`app/selection_parser.py` 负责活动选择，`app/score_parser.py` 负责比分语法。业务校验保留在领域模块，新增指令无需再加一套清洗正则。

`Commands.run` 刷新可信上下文后只规范化一次，再进行分派，连接测试也走同一路径。原 `app.commands.parse`、`strip_mention` 导入保留为兼容入口。内部已生成的业务和 AI 指令改用 `LiteralCommand(text)`，保留已确定的姓名和令牌，避免二次清洗；回调元数据不能选择该类型。语义操作仍调用带权限检查的业务接口，后台 AI 导航/测试不从文字推断群身份。

## 适配器契约

沿用[通用回调字段](INTEGRATION.zh-CN.md)，可选 `text_format`：

| 格式 | 含义 |
| --- | --- |
| `command`（默认） | 已提取业务正文，统一清洗样式；不把正文开头的人员提及再次当作机器人地址。 |
| `mentions` | 先按原文验证位置并保护所有提及，清洗后只移除开头的机器人提及；允许外围有样式标签。 |
| `legacy` | 兼容旧版原始文本，新平台优先使用前两种。 |

以下示例不依赖后台配置名称或群内显示名称是否一致：

```json
{
  "event_id": "message-124",
  "group_id": "example-group",
  "user_id": "example-user",
  "text": "@Club A 注册",
  "text_format": "mentions",
  "mentions": [{"start": 0, "end": 7, "kind": "bot"}]
}
```

位置按原始 `text` 的 **Unicode 码点**计数，从 0 开始，`end` 不包含在范围内。JavaScript 适配器须转换 UTF-16 位置，特别注意 emoji。每项只能包含 `start`、`end`、`kind`；`kind` 为 `bot`（当前接收机器人）或 `user`。范围必须有序、不重叠、不越界，最多 32 项。其他字段、类型拒绝处理。只有 `mentions` 格式允许非空提及列表。

提及范围应来自平台事件，不能靠查找“注册”等业务词猜测。正文内部的机器人提及、人员提及都保留；连续多个开头收件人提示拆开发送。`command` 表示正文已无外层呼叫信息，以前直接传原始 @ 文本的适配器应选择 `legacy` 或提供范围。

后台演练支持相同可选字段，默认 `legacy`，兼容原有演练输入；直接向 `Commands.run` 传字符串也使用 `legacy`。新 Python 对接可构造 `MessageInput`，或调用 `message_input` 校验适配器输入。

## 旧版兼容

1. HTML 实体解码一次；优先使用开头完整的 `<at ...>名称</at>` 边界。
2. 在已知或结构明确的提及边界处理 Unicode 空白，不跳过正文寻找后面的空白。含任意空格的名称优先传入结构化 mentions。
3. 旧纯文本支持单个名称及带空格连字符，例如 `@喂 - 一组专用 注册`。后台名称只是兼容提示，不要求与群名一致，不作为身份依据。允许一个冒号或逗号分隔指令。
4. 仅移除开头的一次提及，保留全部业务参数；连续提及多个对象会拒绝。不会在正文中搜索“注册”等关键词来猜测提及范围。

系统没有别名配置属性。若平台把多词名称与正文都压成普通空格，适配器应传 command、at 标签或 mentions 范围，避免猜测。两个回调入口均接受校验后的格式信息。收到的提及名称仅用于本条回复中的称呼与示例，不写入机器人配置。

## 权限、数据和回归范围

- 回调凭据、机器人/群绑定及发送者 ID 在规范化前独立校验。提及名称、类型和标签不能授予角色或切换发送者。
- 各业务保留开关、场地/场次、会员和权限校验；AI 确认保留本人、原机器人、原群、有效期及执行时复验。
- 旧回调继续使用原始正文计算去重哈希，通用回调继续使用稳定 `event_id`。格式转换不改变重试身份。
- 不需要数据库或配置迁移，保留注册、赛事及权限记录；解析过程不记录原始消息或凭据。
- 回归覆盖名称改动、空格、标点、emoji、各业务指令、两类回调、演练、AI、正文人员提及、实体字符、非法范围、歧义前缀、消息去重及权限拒绝。

普通用户操作说明仍在 `/guide`，管理员说明在 `/guide/admin`；本文供开发维护和平台适配使用。

## 样式与输入格式

三种回调格式及后台演练共用清洗器，支持粗体、斜体、删除线、下划线/颜色 HTML 标签、标题、引用、列表、行内代码、代码块和链接可见标题。实体字符只解码一次；不访问链接地址，也不把图片、脚本、注释、隐藏内容或属性中的文字提取为指令。不支持的非文字内容会提示重发。人员提及 ID、普通网址、账号下划线和表情连接符保留；转义标点作为字面文字，未知标签不直接删除。

| 项目 | 可用写法 |
| --- | --- |
| 排版 | `**报名**`、`<font color="blue">名单</font>`、代码样式包裹的指令 |
| 空格 | 日期分隔符、场次、时间、比分周围可有空格；`报 名 ＋ 两 接 龙`、`取消 报名` |
| 数字字段 | 阿拉伯/全角数字、中文数字、大写数字及圈号1–20，例如 `第２场`、`第贰场`、`第②场` |
| 完整日期 | `2026-11-12`、`2026/11/12`、`2026.11.12`、`20261112`、`二〇二六年十一月十二日` |
| 相对日期 | 今天/今日、明天/明日、后天/后日、昨天/昨日 |
| 24小时制时间 | `20:30`、`２０：３０`、`二十点半`、`二十时三十分` |
| 比分 | `周三赛，第贰场２１－１９`；支持中英文冒号、常见横线/减号、斜线及“比” |
| 级别与同行人数 | `自评 叁 级`、`报名＋两`，仍执行原有等级和人数限制 |

仅在明确的数字字段中转换，不改写姓名、账号或赛事标题中的 `A＋２杯` 等字面内容；`21-19挑战赛` 也可作为赛事名称。无效日期、互相冲突的场地/场次仍会拒绝。不会猜测缺少年份的日期、小数、罗马数字或合并的场次与比分：请写 `12场21:19` 或 `12 21:19`，不要写 `1221:19`。多段文字和多行列表不会自动作为一串操作执行，多步需求沿用 AI 确认流程。
