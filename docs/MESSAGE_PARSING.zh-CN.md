# 统一消息解析

[English](MESSAGE_PARSING.md) · [对接说明](INTEGRATION.zh-CN.md)

## 处理流程

```text
回调认证 / 后台演练认证
  → MessageInput（原文、格式、可选提及范围）
  → normalize_message（仅移除开头呼叫机器人的部分）
  → CommandText（业务正文，不携带身份或权限）
  → parse_selection（场地、日期、场次）
  → Commands（固定业务 / AI 流程）
  → 原有业务开关、范围、会员资格及操作权限校验
```

`app/message_parser.py` 统一负责提及边界、文本格式和输入校验；`app/selection_parser.py` 负责活动选择，`app/score_parser.py` 负责比分语法；业务校验保留在各领域模块。新增指令时不再增加一套去除 @ 的正则。

`Commands.run` 刷新可信上下文后只规范化一次，再进行分派，连接测试也走同一路径。原 `app.commands.parse`、`strip_mention` 导入保留为兼容入口。AI 内部生成的指令使用 `MessageInput(text)`，明确已经是业务正文，不再按聊天提及清理；语义操作仍调用具备权限检查的业务接口。后台 AI 导航/测试接收纯需求文字，不从文字推断群身份。

## 适配器契约

沿用[通用回调字段](INTEGRATION.zh-CN.md)，可选 `text_format`：

| 格式 | 含义 |
| --- | --- |
| `command`（默认） | 适配器已经提取业务正文，仅去除首尾空白；正文中的人员提及、实体字符和姓名均保留。 |
| `mentions` | 原文附带明确的提及位置，仅移除位于开头的第一处机器人提及，可有前导空白。 |
| `legacy` | 兼容旧版原始文本，新平台优先使用前两种。 |

以下示例不依赖后台配置名称或群内显示名称是否一致：

```json
{
  "event_id": "message-124",
  "group_id": "example-group",
  "user_id": "example-user",
  "text": "@Club A 注册",
  "text_format": "mentions",
  "mentions": [{"start": 0, "end": 7, "kind": "bot"}]
}
```

位置按原始 `text` 的 **Unicode 码点**计数，从 0 开始，`end` 不包含在范围内。JavaScript 适配器须转换 UTF-16 位置，特别注意 emoji。每项只能包含 `start`、`end`、`kind`；`kind` 为 `bot`（当前接收机器人）或 `user`。范围必须有序、不重叠、不越界，最多 32 项。其他字段、类型拒绝处理。只有 `mentions` 格式允许非空提及列表。

提及范围应来自平台事件，不能靠查找“注册”等业务词猜测。正文内部的机器人提及、人员提及都保留；连续多个开头收件人提示拆开发送。`command` 表示正文已无外层呼叫信息，以前直接传原始 @ 文本的适配器应选择 `legacy` 或提供范围。

后台演练支持相同可选字段，默认 `legacy`，兼容原有演练输入；直接向 `Commands.run` 传字符串也使用 `legacy`。新 Python 对接可构造 `MessageInput`，或调用 `message_input` 校验适配器输入。

## 旧版兼容规则

1. HTML 实体仅解码一次。
2. 完整的开头 `<at ...>名称</at>` 是旧协议的收件人边界，不依赖显示名称；后续标签不删除。如果平台的首个标签可能是其他人，应通过结构化适配器接入。
3. 否则，在 `@`/`＠` 后匹配完整配置名称：允许水平空白差异，标点按字面匹配，结尾须为空白、冒号、逗号或文本结束，不能跨换行拼接名称。
4. 只移除一处呼叫前缀和一个可选分隔符。仅 @ 没有正文时返回帮助。
5. 未知或不完整的纯文本提及，提示重新选择机器人，不创建会员或执行业务；不再截掉第一个词，也不向后搜索“注册”来猜测指令。

只有纯文本时，无法可靠知道任意显示名称在哪里结束。因此名称匹配仅是兼容处理，不承担身份识别。使用这一兼容方式时，应使后台名称与群内显示名称一致；`command`、`mentions` 格式不依赖机器人名称。

## 权限、数据和回归范围

- 回调凭据、机器人/群绑定及发送者 ID 在规范化前独立校验。提及名称、类型和标签不能授予角色或切换发送者。
- 各业务保留开关、场地/场次、会员和权限校验；AI 确认保留本人、原机器人、原群、有效期及执行时复验。
- 旧回调继续使用原始正文计算去重哈希，通用回调继续使用稳定 `event_id`。格式转换不改变重试身份。
- 不需要数据库或配置迁移，保留注册、赛事及权限记录；解析过程不记录原始消息或凭据。
- 回归覆盖名称改动、空格、标点、emoji、各业务指令、两类回调、演练、AI、正文人员提及、实体字符、非法范围、歧义前缀、消息去重及权限拒绝。
