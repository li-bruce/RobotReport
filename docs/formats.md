# 羽毛球赛制与规则模板

查证日期：2026-10-12。以下是可运行的俱乐部组织模板；计分规则与赛事组织方式分别配置。并不把所有模板或俱乐部积分细则称作羽联官方竞赛规程。

## 已实现的七种独立赛制

| ID / 独立脚本 | 名称 | 人数要求 | 编排与结束条件 |
|---|---|---|---|
| `round_robin.py` | 积分赛 | 单打2—128人；双打须偶数且至少4人 | 个人或固定搭档单循环，每对对手交手一次；全部打完按积分排名 |
| `five_rotation.py` | 五人转 | 恰好5人 | 5场双打，每人打4场、休1场，每两人搭档恰好1次、互为对手恰好2次；个人积分 |
| `five_team.py` | 五羽伦比 | 10—160人，人数须为5的倍数 | 每队5人，随机组队、队内编号固定；团队单循环，累计追逐分登记 |
| `single_elimination.py` | 单淘汰 | 单打2—256人；固定双打至少4人且偶数 | 败者出局；非二次幂人数自动分配轮空；实际对局数为队伍数减1 |
| `double_elimination.py` | 双败淘汰 | 单打2—128人；固定双打至少4人且偶数 | 胜者组、败者组、总决赛；败者组冠军赢总决赛时追加重置决赛，累计两败才淘汰 |
| `group_knockout.py` | 分组淘汰 | 单打至少4人，默认双打至少8人，最多256人；每组至少2个参赛单位且大于晋级数 | 先组内循环，再按每组晋级数形成跨组首轮签表；末位完全同分时显式抽签晋级 |
| `doubles_rotation.py` | 双打轮转 | 4—40人 | 每场选出场较少的4人，优先减少重复搭档；默认场数等于人数，因而每人正好上场4次 |

每个文件均可独立作为 Python 模块运行，不需要数据库或网络：

```bash
python -m app.formats.five_rotation < players.json > draw.json
```

输入示例：

```json
{
  "seed": 20261012,
  "options": {},
  "participants": [
    {"id":"1:0","user_id":"1","name":"甲"},
    {"id":"2:0","user_id":"2","name":"乙"},
    {"id":"3:0","user_id":"3","name":"丙"},
    {"id":"4:0","user_id":"4","name":"丁"},
    {"id":"5:0","user_id":"5","name":"戊"}
  ]
}
```

输出为 `groups`、`matches`、`ranking` 等结构。生产服务自动生成随机种子并持久化抽签结果，重复点击抽签或重启不会洗掉已公布对阵。随机种子用于复现排表，不作为安全令牌。

## 单双打、等级和编排策略（2026-10-13）

新赛事默认 `options.discipline="doubles"`。积分赛、单淘汰、双败淘汰、分组淘汰按两人组成固定队伍；选择 `"singles"` 才按个人编排。双打这些固定队伍赛必须为偶数人数且至少两队。五人转、五羽伦比、双打轮转属于双打玩法，不提供单打模式；五人转仍要求恰好5人，五羽伦比仍按5人一队，不能按普通两人队解释。

群内先发送“组织比赛”，查看当前场次正式且符合会员资格的报名人数及可用赛制，再选择比赛形式。`Tournaments.available_formats(count, discipline, options)` 返回全部赛制的 `available/reason`、人数上下限、人数步长和支持模式，供机器人和管理页共同展示。分组淘汰的最低人数随分组数、每组晋级数调整。

正式人数尚不满足所选赛制时，可按排队顺序加入**最少量的合格替补**，直到达到赛制人数要求；候补不自动参赛，也不会删减已有正式成员来凑五人转等固定人数赛制。`available_formats(..., substitute_count=N)` 返回 `selected_count/substitutes_needed`，`planning_candidates()` 分别返回正式和替补队列。参赛快照保存 `source_category`，对战表前列明补齐的替补；单场容量调整不会重绘既有赛事。实名代报名保留所填姓名与“代报”标签，不继承代报者的等级或会员组。

| `assignment_strategy` | 中文名称 | 实际编排方式 |
|---|---|---|
| `random` | 随机分配 | 使用已保存随机种子打乱后组队和分组 |
| `seeded` | 种子分布 | 按已审核等级排序，同级随机；高等级先分散到各队，队伍按强度排序后进入标准种子签位；分组使用蛇形分配，使高等级种子分散 |
| `balanced` | 平均分布 | 按等级从高到低，将下一人分配到当前总等级最低且未满的队伍；分组同样按总等级均衡，控制组人数差不超过1 |
| `high_low` | 高带低 | 最高和最低等级交替配对，逐步向中间收拢；五人队延续交替高低顺序，组间按总等级均衡 |

等级仅来自已审核的会员标签（1—9级），未评级和未实名同行的算法数值为0，显示为“无级别”。0不代表技术水平判断。以上为俱乐部编排方法，不是国际羽联认可的能力评级。高低搭配和均衡仅优化等级这一项，不假定性别、位置或体力。五人转的全部搭档组合由公平轮转规则固定，因此仅允许随机排位；双打轮转保持出场公平、先减少重复搭档，再按所选策略优化每场配对。单打没有搭档，高带低策略不会虚构双人队伍。

`plan.assignment` 和抽签审计保存算法版本、策略、随机种子、等级快照。旧赛事已生成的对阵、比分和参赛身份不会因升级而重新抽签；旧 `team_size=1` 赛事继续按单打显示。赛事报名、分组、对战、积分消息均输出标准 Markdown 表格，姓名旁显示审核等级。金山协作发送层可将表格转换为图片，避免客户端不支持 Markdown 表格造成文字堆叠。

大型赛事可设置 `options.eligibility={"min_level":1,"max_level":3,"allowed_group_ids":[1,2]}`。等级上下限同时满足，允许组别为“任一组匹配”，空条件表示不限。即使不限等级，仍须会员审核通过；有限制的活动不允许替无身份同行报名，同行需独立注册审核。赛事报名在数据库事务内再次核验资格，界面隐藏按钮不能替代服务端权限检查。

## 五羽伦比和五人转的区别

五羽伦比采用**五人一队、团队得分、队内组合轮换**。杭州亚组委机关工会的2022年赛事采用每队5人、组合12/23/34/45/51轮换，总分50分的形式。本服务以此作为默认组织模板：`points=50, cap=50, win_by=1, best_of=1, relay_segment=10`。队内编号和名单在抽签后锁定；计分者登记每场最终累计比分，例如50:43。服务生成换人顺序提示，不承担逐拍判罚或现场换人裁判工作。[杭州亚组委赛事说明](https://www.hangzhou2022.cn/xwzx/jdxw/ttxw/202211/t20221112_53583.shtml)

该名称没有唯一的通用分制。例如中国科学院大学2019年组织的赛事也是五人一队，但采用75分累计制。因此75分可配置 `points=75, cap=75, relay_segment=15`；100分可以配置 `points=100, cap=100, relay_segment=20`，后者属于本服务允许的俱乐部扩展，不声称与所有100分民间换人办法相同。主办方需在发布报名时明确采用哪种版本。[国科大主办方赛事记录](https://news.ucas.ac.cn/xydt/331b48159015434f8f52f4fe9de4d947.htm)

五人转在本服务中明确指**五个人轮换双打搭档、按个人统计成绩**。未查到统一的官方五人转规程；本模板使用可验证的公平排表：每个人轮空一次，每对搭档仅配合一次。羽林决也存在使用“双打轮转排位赛”分类且活动名称含“五人转”的活动，表明名称不能替代具体规程。本服务始终展示实际人数、搭档和记分规则。[羽林决赛事索引](https://www.yulinjue.com/games_110115_end/8/)

五羽伦比原活动有性别配额或水平配对要求；当前模型有管理员审核的会员等级，但不采集或推断性别，不宣称自动满足混合团体性别配额。需要性别限制时由组织者在报名备注和线下核验中落实。

## 计分、排名及同分

- 日常模板默认**一局21分**，20平后需领先2分，最高30分；这是一局制俱乐部安排。设置 `best_of=3` 可使用三局两胜；三局两胜必须录入2或3局且在一方胜两局后立即结束，不接受额外局。
- 支持 `points`、`cap`、`win_by`、`best_of` 组合。校验21:20、22:19、30:20等不合法终场分，接受22:20、30:28、30:29。21分计分和封顶依据羽联的简化规则；一局制和组合赛制属于显式配置。[BWF简化规则](https://system.bwfbadminton.com/documents/folder_1_81/Regulations/Simplified-Rules/Simplified%20Rules%20of%20Badminton%20-%20Dec%202015.pdf)
- 日本羽毛球协会公告确认，羽联通过的三局15分制度将于2027-01-04实施。现有赛事不会因为服务器跨年而被自动改分；主办方可以在抽签前设置 `points=15, cap=21, win_by=2, best_of=3`。抽签后冻结计分规则，保证历史可复现。[日本羽毛球协会2026-04-26公告](https://www.badminton.or.jp/news/detail/2156)
- 积分赛、五人转、五羽伦比及分组循环的本地排名依次为：**胜场 → 局净胜 → 分净胜**。完全相同则并列，不靠ID暗中决定名次。双打轮转允许用户调整场数导致出场次数不等，故第一指标使用**胜率**，随后局净胜、分净胜。这些是本服务公开的俱乐部排序细则，不声称采用所有官方赛事的同分处理办法。
- 分组赛中若同分仅影响展示顺序、不会影响谁出线，则保留并列显示；若完全同分跨越晋级名额边界，赛事保留运行状态，`plan.awaiting_tie_draw=true`。组织者通过管理页的“同分抽签并晋级”操作调用 `transition(id, 'advance', actor, is_admin)`；抽签候选人、入选者和操作者写入审计。已结束的小组赛不会被重打，重启后仍等待该操作。
- 单淘汰、双败淘汰冠军由最后决赛的胜者决定，不能以累计胜场数代替。双败赛未触发重置决赛时实际场数为`2N-2`，触发时为`2N-1`（N为参赛单位）；轮空不虚构比分、不算失败。
- 分组循环再淘汰的组织方式可见国内正式赛事规程，但本服务的分组数量、晋级人数和同分抽签是显式俱乐部配置。[福建省2025年青少年比赛规程](https://jyt.fj.gov.cn/jglb/tywsysjyyyywzc/xxty/202507/t20250702_6960756.htm)

## 流程、权限和数据恢复

大型比赛：草稿 → 开放报名（受报名起止时间约束）→ 报名关闭 → 抽签 → 开赛 → 暂停/继续 → 完赛 → 归档。关闭报名可手动执行，也会在到期时自动执行并产生持久化通知。暂停不清空比分，不会重新抽签。

日常比赛通过“组织比赛”选择流程，由当天指定场次符合资格的正式报名及必要替补快照创建，确定赛制后生成对阵并开赛。创建者即负责人，管理员网页创建时可通过`organizer_user_id`指定已审核会员。负责人可记分、修正、暂停、恢复和关闭；旧`members/leader`配置不授予权限。每日趣味赛和大型赛事均有独立赛事职务：负责人可以任命审核通过且有明确生效/失效时间的记分员、协调员；新增或调整负责人必须由后台管理员执行。记分员只登记尚无比分的比赛；协调员只维护公开说明、集合说明、协调安排和比赛日程，不因职务获得记分或后台管理权限。会员资格撤销后，赛事职务即时失效。

已有比分仅本赛事负责人或后台管理员可修正，且必须提交当前 `expected_version`。修正会保留前后分数与操作者；若会更换晋级者且下游已产生比分，拒绝修正，避免悄悄改写已打比赛。上游小组成绩不能在淘汰阶段已记分后修改。未打的下游签表可安全重算，并使旧版本/旧场次ID失效。`close`动作进入`cancelled`终态，保留赛程与已录比分，不能恢复，不生成未完成赛事的冠军；仍可归档。

数据库保存参赛快照、抽签种子、队伍、对阵依赖、比分版本、临时角色、状态和所有操作记录。赛事属于统一后台；从不同机器人或群访问的是同一份赛事记录。恢复候选来自同一后台与当前可用场地，按当前报名人与原参赛人的交集/并集比例、相同人数、日期、更新时间排序。恢复不会悄悄替换原参赛者；新增或缺席名单单独返回，负责人可决定继续原比赛还是新建活动。

赛事照片、附件和群发功能由外层上传/消息服务提供；赛事引擎负责稳定的赛事ID和生命周期，附件关联该ID。赛事通知独立绑定多个机器人下的群通道，群内发起时默认绑定来源通道；后台创建且未绑定通道时不会隐式群发。保存绑定时校验通道启用状态与场地范围。公开说明、实际组队方法、规则说明、集合说明、内部协调事项分别维护；抽签后不允许更改组队算法，说明文字的编辑不会重绘对阵。场地时间由负责人或协调员明确安排；同场地、同球场名称、相同开始时间的待打比赛冲突会拒绝并回滚整批更新。没有配置比赛时长，因此不检测不同开始时间的区间重叠，也不自动调度现场球场。
