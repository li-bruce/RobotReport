# Deployment and data migration

[English](DEPLOYMENT.md) | [简体中文](DEPLOYMENT.zh-CN.md) · [README](../README.md)

Applies to v2.19. Use the same source revision and `requirements.lock` in testing and production. Python 3.10 is the verified runtime.

## Configuration

| Setting | Purpose |
| --- | --- |
| `ROBORT_STATE_DIR` | Absolute path to the private state directory; default: `state/local` inside the checkout. |
| `ROBORT_LIVE_SEND` | `1`/`true` enables real delivery; `0`/`false` or blank disables it. Invalid values fail startup. |
| `ROBORT_PUBLIC_BASE_URL` | Public origin used to generate bot callbacks, e.g. `https://club.example.org`. |
| `ROBORT_ADMIN_TOKEN` | Optional bootstrap bearer token. Normally omit it and use the private token generated by `scripts.bootstrap`. |
| Admin → public URL | Business configuration `public_base_url`, used for registration/media links. Set it to the same public origin. |
| Admin → AI | Provider key, model, enabled switch and confirmation expiry (1–1440 minutes; default 5). |

The application automatically reads **`.env.local`**. Use `ROBORT_ENV_FILE` to select a persistent file outside the release directory. The public template has empty values only; AI keys and per-bot connection settings are described in [Local configuration](ENVIRONMENT.md). Nonempty process variables override the file; admin-managed settings write back to the local file. Business dates and reminder times use **Asia/Shanghai (UTC+08:00)**. Defaults are 09:30 opening notice, 17:30 closing reminder and 18:00 roster; registration remains available all day when its session is eligible.

## New installation

1. Install Python 3.10 with `venv` support. Download/clone the source and create a virtual environment. Install `requirements.lock`.
2. Create a dedicated service account and directories. Example layout:

   ```text
   /srv/robort/current/       Source checkout
   /srv/robort/venv/          Python environment
   /srv/robort/state/         Private state owned by the service account
   /srv/robort/state/.env.local     Private service environment
   ```

3. As the service account, initialize **empty production state** without demo users:

   ```bash
   cd /srv/robort/current
   /srv/robort/venv/bin/python -m scripts.bootstrap --state /srv/robort/state
   /srv/robort/venv/bin/python -m scripts.set_admin_password --state /srv/robort/state
   ```

4. Copy `.env.example` to `/srv/robort/state/.env.local`, owned and writable only by the service account. Fill these values; remaining fields may stay blank:

   ```ini
   ROBORT_STATE_DIR=/srv/robort/state
   ROBORT_LIVE_SEND=0
   ROBORT_PUBLIC_BASE_URL=https://club.example.org
   ```

5. Install a service such as `/etc/systemd/system/robort.service`, adjusting account and paths:

   ```ini
   [Unit]
   Description=Robort badminton club platform
   After=network-online.target
   Wants=network-online.target

   [Service]
   Type=simple
   User=robort
   Group=robort
   WorkingDirectory=/srv/robort/current
   Environment=ROBORT_ENV_FILE=/srv/robort/state/.env.local
   Environment=PYTHONDONTWRITEBYTECODE=1
   ExecStart=/srv/robort/venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 9874 --workers 1 --no-access-log --proxy-headers --forwarded-allow-ips=127.0.0.1
   Restart=on-failure
   RestartSec=3
   UMask=0077
   NoNewPrivileges=true
   PrivateTmp=true
   ProtectHome=true
   ProtectSystem=strict
   ReadWritePaths=/srv/robort/state

   [Install]
   WantedBy=multi-user.target
   ```

6. Reload systemd and start **this service only**. Configure TLS at a reverse proxy, log in, set the public URL and configure venues, schedules and bots.
7. After checking the connection settings, change `ROBORT_LIVE_SEND=1` and restart this service. Mention each bot with `帮助` and verify the reply.

Keep one application worker and one active service per state directory. Do not point a test instance at production state.

## Reverse proxy and network

Expose HTTPS to the Kingsoft server and to users opening registration pages. Keep port 9874 on loopback behind the proxy. Open the actual public HTTPS port in the host firewall, hosting-panel firewall and cloud security group when those are present.

Example Nginx location inside an already configured HTTPS server:

```nginx
location / {
    proxy_pass http://127.0.0.1:9874;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    client_max_body_size 11m;
    proxy_read_timeout 120s;
    access_log off;
}
```

Adjust trusted proxy addresses if your proxy runs elsewhere. Callback and personal-registration URLs contain credentials; avoid recording full URLs in proxy/access logs. The callback must be reachable without the web administrator login. Do not remove its token or `robot_key` verification.

## Stored data

```text
state/
  registry.sqlite3                 Bots, groups, authentication and credentials
  admin.local.json                 Private script/API bearer token
  workspace/
    business.sqlite3              Members, sessions, events, renewals, AI conversations, audit
    uploads/                      Uploaded files and photos
    tables/                       Generated message table images
  bots/<bot_id>/
    transport.sqlite3             Inbox/outbox, deduplication, AI plans and conversation state
    callback.local.json           Private callback credential
```

Older installations may retain additional migration files and legacy databases. Keep them in a complete backup. The state directory contains personal information and secrets; file permissions protect it, but application-level encryption at rest is not provided. Keep the whole directory out of Git.

## Backup, move and restore

For a consistent recovery point across the business database, registry, transport databases and files:

1. Record the source revision, dependency lock and service environment.
2. Stop only the Robort service during an agreed brief maintenance window.
3. Archive the **complete state directory** and service configuration to a private backup location. Record a SHA-256 checksum and check that the archive can be listed/read. Start the original service again if you are only taking a backup.
4. On the new host, install the same source and dependencies. Restore into a fresh state directory; preserve ownership and private permissions. Do not run demo bootstrap or reset scripts against restored data.
5. Initially start with real sending disabled. Check SQLite integrity, user/session/event counts, login and media access. Keep testing read-only: simulation mode still writes if business actions are invoked.
6. If the domain changes, edit the local public origin or the admin page setting (they synchronize), then update callbacks in Kingsoft. Retained outgoing keys and callback credentials need not be regenerated merely because the host changes.
7. Stop the old instance before enabling real sending and scheduling on the new one. Verify a real bot reply and the health endpoint.

SQLite's backup API can create an online copy of one database. Independent online copies are **not automatically a consistent cross-database recovery point**. Do not copy only `business.sqlite3` while the service is active.

After new registrations or scores reach the new service, restoring an older snapshot could discard them. Preserve the new state before planning a rollback.

## Upgrade and verification

Test the new revision against an isolated copy first. Legacy single-bot migration can be checked using:

```bash
python -m scripts.verify_workspace_migration \
  --source /path/to/consistent-legacy-snapshot \
  --destination /path/to/new-isolated-copy \
  --source-is-snapshot
```

The destination must not exist. Multiple independent legacy business databases need a reviewed mapping; the tool does not silently merge them. `scripts/reset_business_data.py` is an explicit destructive maintenance tool, not an installation or upgrade step.

Run `python -m pytest -q`, the frontend checks and applicable [browser suites](../scripts/mobile_browser/README.md). After deployment, verify `/healthz`, password login, the member/admin guides, callback validation and a controlled bot reply. Preserve existing enrollment and match records.
